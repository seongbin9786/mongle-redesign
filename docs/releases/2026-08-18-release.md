## 1. 왜 바꿨나

홈은 **관계태그 칩**(가족·친구·직장…)으로 사람을 걸러 보는 화면이었다. 세 가지가 걸렸다.

1. **칩은 보기 전에 고르기를 요구한다.** 홈에서 하고 싶은 일은 "내 관계를 본다"인데, 화면 맨 위
   한 줄이 늘 "무엇으로 거를까"를 먼저 묻고 있었다.
2. **관계태그는 사실 분류이지 마음의 거리가 아니다.** `직장`은 그 사람이 누구인지 말하지만,
   내가 그 사람을 어떻게 여기는지는 말하지 않는다. 사용자가 실제로 묶고 싶어 하는 축
   (`최애` · `말잇못` · `스쳐지나간`)은 태그 체계에 들어갈 자리가 없었다.
3. **필터는 지도를 좁힐 뿐 다른 세계를 열지 않는다.** 궤도 홈의 은유는 우주인데, 칩 필터는
   같은 우주에서 사람 몇을 지우는 조작이라 은유와 따로 놀았다.

그래서 칩을 걷어내고, 사용자가 **이름 붙인 인물 묶음(존)** 을 좌우로 넘기는 **우주**로 바꿨다.
고르지 않아도 첫 장(`전체`)이 열리고, 더 보고 싶을 때만 옆으로 넘긴다.

덧붙여, 지금까지의 관계 지도는 전부 **나 ↔ 그 사람**이었다. **그 사람들끼리**의 관계는 데이터도
화면도 없어서, 이번엔 **프로토타입 화면 하나**로 그 질문을 먼저 만져 볼 수 있게 했다.

## 3. 무엇이 어떻게 바뀌나

### 3.1 홈 — 우주 스와이프

- 우주 목록은 **`전체` + 존 순서 + `존 만들기`**다. 첫 장은 언제나 `전체`, 마지막 장은 존을
  만들러 가는 안내다(존 상한 12개에 닿으면 접는다).
- **존이 0개여도 넘길 곳이 있다.** 스와이프는 흔적을 남기지 않는 제스처라 넘길 장이 없으면
  기능이 있다는 사실 자체가 드러나지 않는다 — 존이 없는 사용자는 `전체`에서 한 번 넘겨
  `아직 만든 존이 없어요` + `[＋ 존 만들기]`를 만난다.
- 좌/우 스와이프 또는 인디케이터 화살표로 넘긴다. 양 끝에서 멈추고 순환하지 않는다.
- 존 우주에서는 담기지 않은 사람을 **흐리게 두지 않고 아예 뺀다**. 흐림은 `멀어진 관계` 전용
  표현이라 섞지 않는다.
- 우주가 바뀌면 새 궤도가 넘긴 방향에서 들어오며 다시 그려진다(420ms). 나가는 우주를 함께
  그리지 않는 이유는 눈금이 두 겹으로 보이면 어느 쪽이 내 우주인지 흐려지기 때문이다.

**제스처 충돌을 어떻게 풀었나** — 궤도 지도는 이미 팬·핀치를 쓴다. 스와이프를 바깥 래퍼에서
따로 받으면 같은 포인터를 두 곳이 해석해 서로를 삼킨다. 그래서 판정을 `use-orbit-viewport.ts`
**한 곳**으로 모으고, 우주 이동으로 읽는 조건을 좁게 잡았다:

1. 기본 보기(확대·이동하지 않은 상태)에서 시작했고,
2. 가로 이동이 세로의 1.4배를 넘고,
3. 손을 뗄 때 가로 이동이 56px 이상일 때.

확대해서 보는 중의 가로 드래그는 **언제나** 지도를 미는 뜻이다. 제스처의 정체는 임계값을 넘는
첫 움직임이 확정하고 끝까지 바뀌지 않는다.

### 3.2 존(zone)

- 사용자가 이름 붙인 인물 묶음이다. 이름 1~10자, 사용자당 최대 12개, 색은 선택.
- **관계태그와 다른 축**이다. 관계태그는 "이 사람이 누구인가", 존은 "내 마음에서 어디쯤인가".
  둘을 합치지 않는다.
- **한 사람이 여러 존에 속할 수 있다.** 배타적 분류가 아니라 겹쳐 보는 렌즈다.
- 설정 > **존 관리**에서 만들고 고치고 지운다. 존 줄을 누르면 인물 담기 화면으로 들어간다.
  인물 할당은 고르는 동안 서버를 건드리지 않고 **저장 한 번에 전체 교체**한다.
- 존을 지워도 사람은 지워지지 않는다.

### 3.3 인물관계도 (프로토타입)

- 홈 헤더 오른쪽 위 `인물관계도` 버튼으로 들어간다(하단 탭은 늘리지 않는다).
- 인물을 올리고, 인물 옆 ＋를 다른 인물로 끌어 잇는다. 아바타에서 시작한 드래그는 이동,
  ＋ 손잡이에서 시작한 드래그는 연결이다.
- **저장하지 않는다.** 서버도 localStorage도 쓰지 않고 화면을 나가면 사라지며, 화면이 그 사실을
  먼저 말한다. 저장되는 것처럼 보이는데 사라지는 화면이 더 나쁘고, 임시 로컬 저장은 나중에
  마이그레이션이 아니라 폐기 대상이 되어 사용자 기기에 남기 때문이다.
- 관계의 종류·강도·방향은 이번 범위가 아니다 — 데이터가 없는 상태에서 UI가 먼저 스키마를
  정해 버리면 그게 제약이 된다.

## 4. API 변경

신규 `/api/v1/zones` (전부 JWT 필요). 상세 계약 → [06-zone mustpass](../../backend/docs/mustpass/06-zone.md)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/zones` | 내 존 목록(각 존의 `personIds` 포함) |
| POST | `/api/v1/zones` | 존 생성 (`name`, `color?`) |
| PATCH | `/api/v1/zones/{id}` | 이름·색 변경 |
| DELETE | `/api/v1/zones/{id}` | 존 삭제(소프트) — 인물은 그대로 |
| PUT | `/api/v1/zones/{id}/persons` | 인물 **전체 교체** |

**관계 지도에 존 필터를 붙이지 않은 이유:** 우주를 넘길 때마다 서버를 다녀오면 스와이프 도중
지도가 비어 은유가 깨진다. 관계 지도는 한 번만 받고, 존 응답의 `personIds`로 클라이언트가 나눈다.

**호환성:** 기존 API는 그대로다. `GET /api/v1/home/relation-map`의 `relationTagChipIds` 파라미터는
서버에 남아 있지만 프런트가 더 이상 쓰지 않는다(다른 클라이언트를 깨지 않기 위해 유지).

**스키마:** `zone` · `zone_person` 테이블이 `ddl-auto: update`로 생성된다(마이그레이션 스크립트 없음).

## 5. 데이터 마이그레이션

없다. 기존 사용자는 존이 0개라 홈이 `전체`로 그대로 열리고, 한 번 넘기면 `존 만들기` 안내를 만난다.
데모 시드(`POST /api/v1/seed`)에는 존 3개(`최애존`·`말잇못존`·`스쳐지나간존`)를 추가해, 새로
시드한 계정에서 스와이프가 바로 관찰된다. 이미 시드된 계정은 멱등 규칙에 따라 다시 시드되지
않으므로 존이 비어 있다(설정에서 직접 만들면 된다).

## 7-1. 운영 메모 — 백엔드 재기동 필요

존 API는 **새로 빌드한 백엔드에서만** 뜬다. 프런트 `pnpm dev:vite`는 기본으로 `localhost:18080`
(도커 백엔드)을 프록시하므로, 이 회차 코드로 다시 띄우지 않으면 `GET /api/v1/zones`가 404가 되고
홈은 존을 못 불러온다(우주가 `전체` + `만들기` 두 장으로만 보인다).

```bash
cd backend && docker compose up -d --build     # 도커(18080)
# 또는 ./gradlew bootRun                        # 로컬 H2(8080) → BACKEND_URL=http://localhost:8080 pnpm dev:vite
```
