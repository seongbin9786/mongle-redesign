# 07. 인물관계도(RelationGraph) — mustpass

> 목적: 인물관계도 도메인 코드가 반드시 지켜야 할 불변식을 확정.
> 근거: 프론트 계약 = [frontend/docs/mustpass/relation-graph-prototype.md](../../../frontend/docs/mustpass/relation-graph-prototype.md).
> 공통 계약(에러 포맷·소유 컨텍스트·한도)은 [00-infra.md](00-infra.md) 를 그대로 소비한다.

## 정체 (must)

- 인물관계도는 **인물끼리의 관계**를 사용자가 손으로 그려 둔 한 장이다. 홈의 궤도(나 ↔ 그 사람)와
  **다른 축**이라 서로를 대체하지 않는다.
- 사용자당 **한 장**이다. 자원 id 가 없고, 경로도 단수(`/api/v1/relation-graph`)다.
- 그래프는 **노드(올린 인물 + 좌표)** 와 **선(인물↔인물 연결)** 으로 이룬다.
  좌표까지 서버가 드는 이유: 관계도는 배치로 읽는 그림이라, 자리를 잃으면 선만 남아도 같은 그림이 아니다.

## 영역(그룹) (must)

- 영역은 지도 위 한 **구획**이다. 서버가 정의하는 분류가 아니라 사용자가 그어 둔 구역이라,
  관계태그(chip)를 **참조하지 않고 이름·색을 복사**해 든다 — 태그 이름이 바뀌어도 지도 위
  구획은 사용자가 놓아둔 그대로여야 하고, 태그를 지웠다고 지도에 구멍이 나서도 안 된다.
- 노드는 서버 id 가 아니라 **key**(예: `tag:12`)로 영역을 가리킨다. 그래프는 통째로 교체되는데
  id 로 묶으면 저장할 때마다 새 id 를 받아 와야 하고, 그 왕복 동안 화면과 서버가 갈린다.
- key 는 지도 안에서 하나뿐이다(겹치면 첫 등장만). **key 가 빈 영역은 버린다** — 노드가 가리킬 수 없다.
- 이름은 1~20자(`NAME_MAX`). 비면 400 `REQUIRED_FIELD`, 초과면 400 `LENGTH_EXCEEDED`.
- 폭·높이는 최소값(80) 아래로 내려가지 않게 **올린다**. 0 짜리 구역은 화면에서 선 하나로 보여 만질 수 없다.
- **없는 영역을 가리키는 노드는 거절하지 않고 영역만 떼어 놓는다**(groupKey = null). 인물은 지도에
  남아야 하고, 구획 하나가 어긋났다고 그림 전체를 저장 못 하게 하는 쪽이 더 나쁘다.
- 사람이 다 빠진 **빈 영역도 남긴다**. "여기 자리를 잡아 뒀다"는 정상 상태이고, 지우면 사람을
  잠깐 뺀 사이 지도의 구획이 무너진다.

## 연결(선) (must)

- 선은 **영역과 무관하다.** 다른 구역의 인물끼리도 이어진다 — 구획은 보기 위한 것이지
  이을 수 있는 범위가 아니다. 서버는 영역으로 선을 거르지 않는다.

- 선에는 **방향이 없다.** 저장 전에 작은 personId 를 `fromPersonId` 로 정렬한다 —
  (A,B)와 (B,A)가 두 행으로 갈리면 같은 관계가 화면에 두 줄로 나온다.
- 같은 쌍이 여러 번 오면 **첫 등장만** 남긴다. 중복은 실수지 위반이 아니라 에러 대신 접는다
  (존 인물 할당과 같은 판단).
- **자기 자신과의 연결**과, 양끝이 `nodes` 에 없는 연결은 **버린다**(에러 아님) — 선은 양끝이 다 지도에 있어야 성립한다.
- `intimacy` 는 **0~100**. 범위 밖 값은 거절하지 않고 **조인다(coerce)** — 눈금 밖 값은 사용자의 의도가
  아니라 클라이언트 사고라, 저장 실패로 그림을 통째로 잃는 쪽이 더 나쁘다.
- `intimacy` 는 홈 궤도의 **계산된 친밀도와 다른 값**이다. 여기 값은 "내가 보기에 둘이 얼마나 가까운가"라
  서버가 만남 기록으로 대신 계산해 줄 근거가 없다. 두 값을 섞지 않는다.
- `note`("어떻게 아는 사이")는 선택이고 최대 **200자**(`MEMO_MAX`). 초과면 400 `LENGTH_EXCEEDED`.
  공백만 남는 메모는 `null` 로 접는다(빈 문자열과 null 두 가지 '없음'을 만들지 않는다).

## 저장 (must)

- 저장은 **전체 교체**(`PUT`). 부분 추가·삭제 API 를 두지 않는다 — 화면이 캔버스라 한 번의 조작이
  노드·선·좌표를 동시에 바꾸고, 쪼개면 중간 상태가 서버에 남아 화면과 갈린다.
- 노드의 인물은 **내 소유·active 인물만**. 하나라도 아니면 통째로 404 `NOT_FOUND` —
  일부만 반영하면 화면과 서버가 갈린다(존 인물 할당과 같은 규약).
- 같은 인물이 두 번 오면 첫 등장만 남긴다.
- 교체는 노드·선 모두 **하드삭제 후 재삽입**(조인 엔티티 규약, 컨벤션 §1).

## 조회 (must)

- 그린 적이 없으면 **빈 목록**(`{nodes: [], links: []}`) — 204 가 아니다. 빈 캔버스도 정상 상태다.
- **소프트삭제된 인물은 빠지고**, 그 인물에 걸린 선도 함께 빠진다. 지운 사람이 관계도에 유령으로
  남으면 안 된다(존과 같은 규약). 저장된 행 자체는 지우지 않는다 — 인물이 되살아나면 그림도 돌아온다.
- 순서는 id 오름차순으로 고정한다(표시 결정성).

## 계약·엣지

| 상황 | 입력 | 기대 결과 |
|---|---|---|
| 처음 열기 | `GET /api/v1/relation-graph` | 200 `{nodes: [], links: []}` |
| 역방향 중복 | `links: [(A,B), (B,A)]` | 한 줄만 저장, `from` = 작은 id |
| 자기 연결 | `links: [(A,A)]` | 버림(에러 아님) |
| 노드에 없는 인물의 선 | `links: [(A,Z)]`, `nodes: [A]` | 버림(에러 아님) |
| 친밀도 범위 밖 | `intimacy: 180` / `-5` | `100` / `0` 으로 조임 |
| 남의 인물 | `nodes: [{personId: 남}]` | 404 `NOT_FOUND` (전체 거절) |
| 영역 key 중복 | `groups: [(k), (k)]` | 첫 등장만 저장 |
| 영역 key 빈 값 | `groups: [{key: ""}]` | 버림(에러 아님) |
| 없는 영역 참조 | `nodes: [{groupKey: "없음"}]` | 인물은 남고 `groupKey`만 null |
| 영역 크기 0 | `width/height: 10` | 최소값(80)으로 올림 |
| 구역이 다른 두 인물 | `links: [(A@g1, B@g2)]` | 그대로 저장(영역으로 거르지 않는다) |
| 메모 201자 | `note` 201자 | 400 `LENGTH_EXCEEDED` |
| 메모 공백만 | `note: "   "` | `null` 로 저장 |
| 인물 삭제 후 조회 | 인물 A 소프트삭제 | A 노드와 A 에 걸린 선이 응답에서 빠짐 |
