# 06. 존(Zone) — mustpass

> 목적: 존 도메인 코드가 반드시 지켜야 할 불변식을 확정.
> 근거: (PRD 01 §12 존과 우주) = SSOT, (docs/releases/2026-08-18-release.md) = 이번 변경의 배경.
> 공통 계약(에러 포맷·소유 컨텍스트·소프트삭제·한도)은 [00-infra.md](00-infra.md) 를 그대로 소비한다.

## 정체 (must)

- 존은 **사용자가 이름 붙인 인물 묶음**이다(예: `최애존` · `말잇못존` · `스쳐지나간존`).
  홈에서 좌우로 넘기는 **우주 한 장**이 존 하나에 대응한다.
- 존은 **전부 개인 소유**다(`ownerId` 필수). 공통 존·기본 시드 존은 없다 — 이름은 사용자의 언어라서
  제품이 미리 정해 줄 수 없다. (`전체` 우주는 존이 아니라 프론트가 만드는 가상 우주다.)
- 존은 관계태그와 **다른 축**이다. 관계태그가 "이 사람이 누구인가"(가족·직장)라면 존은
  "내 마음에서 어디쯤인가"다. 서로를 대체하지 않으며 한쪽으로 합치지 않는다.

## 생성 (must)

- 이름은 **1~10자**(`ZONE_NAME_MAX`). 비면 400 `REQUIRED_FIELD`("존 이름을 입력해 주세요."),
  초과면 400 `LENGTH_EXCEEDED`.
- **내 존 안에서 이름 중복 금지**(active 기준). 위반 시 409 `DUPLICATE`.
  (소프트삭제된 존의 이름은 다시 쓸 수 있다.)
- 존은 사용자당 **최대 12개**(`ZONE_MAX`). 13번째는 400 `ZONE_LIMIT`.
  좌우 스와이프로 순회하는 화면이라 개수가 늘면 "다음 우주"가 탐색이 아니라 노동이 된다.
- 새 존은 내 존 중 **마지막 순서**(`displayOrder`)로 붙는다.
- 색(`color`)은 선택이다. 없으면 null 이고 프론트가 무채색으로 그린다.

## 조회 (must)

- 목록은 **내 소유·active 존만**, `displayOrder` 오름차순 → 동률이면 id 오름차순(표시 결정성).
- 각 존은 **소속 인물 id 목록(personIds)** 을 함께 낸다 — 프론트가 관계 지도 노드를 이 id 로
  나눠 우주를 만든다. 순서는 할당 순서(`displayOrder`)를 보존한다.
- personIds 에는 **소프트삭제된 인물을 포함하지 않는다.** 지운 사람이 우주에 유령으로 남으면
  안 되고, 존은 과거 참조를 보존해야 하는 라벨(칩)과 달리 "지금의 묶음"이기 때문이다.

## 인물 할당 (must)

- 할당은 **전체 교체(PUT)** 다. 부분 추가·삭제 API 를 따로 두지 않는다 — 설정 화면이
  체크박스 목록이라 저장 한 번에 지금 상태를 그대로 보내는 편이 규칙이 하나로 남는다.
- 요청의 personId 는 **내 소유·active 인물**만 허용한다. 하나라도 아니면 404 `NOT_FOUND`.
- **중복 id 는 첫 등장만 남기고 접는다**(에러 아님).
- 빈 목록을 보내면 그 존은 비워진다(존 자체는 남는다).
- **한 인물이 여러 존에 속할 수 있다.** 존은 배타적 분류가 아니라 겹쳐 보는 렌즈다.
- 인물을 소프트삭제해도 **할당 행은 지우지 않는다** — 조회에서 걸러진다.
  (되살릴 여지를 남기고, 삭제 경로가 존을 몰라도 되게 한다.)

## 수정·삭제 (must)

- 이름·색만 바꾼다. 소유자·id 는 바뀌지 않는다.
- 이름 변경의 글자수·중복 검증은 생성과 같다(중복 검사에서 자기 자신은 제외).
- 없는 존·타인의 존은 404 `NOT_FOUND`.
- 삭제는 **존 소프트삭제 + 할당 행 하드삭제**다. 존은 과거 기록이 참조하지 않으므로
  라벨(칩)처럼 이름을 보존할 이유가 없다 — 남는 조인 행이 다음 존 id 와 섞이는 쪽이 더 나쁘다.
- **존을 지워도 인물은 지워지지 않는다.** 묶음이 사라질 뿐이다.

## 계약·엣지

| 상황 | 입력 | 기대 결과 |
|---|---|---|
| 이름 없음 | POST `{ "name": "  " }` | 400 `REQUIRED_FIELD` — "존 이름을 입력해 주세요." |
| 이름 11자 | POST `{ "name": "1234567890가" }` | 400 `LENGTH_EXCEEDED` |
| 이름 중복 | 이미 `최애존` 보유 후 POST `최애존` | 409 `DUPLICATE` |
| 지운 존과 같은 이름 | `최애존` 삭제 후 POST `최애존` | 201 (active 만 중복 대상) |
| 13번째 존 | POST | 400 `ZONE_LIMIT` |
| 남의 인물 할당 | PUT persons `[타인 personId]` | 404 `NOT_FOUND` |
| 지운 인물 할당 | PUT persons `[soft-deleted id]` | 404 `NOT_FOUND` |
| 같은 인물 두 번 | PUT persons `[7, 7, 8]` | 200 — `[7, 8]` 로 접힘 |
| 인물 할당 후 인물 삭제 | 인물 소프트삭제 | GET 의 personIds 에서 빠짐(할당 행은 남음) |
| 존 삭제 | DELETE | 204 — 존 소프트삭제, 인물은 그대로 |
| 타인 존 수정 | PATCH | 404 `NOT_FOUND` |
