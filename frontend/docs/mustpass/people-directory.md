# mustpass — 사람 목록(디렉토리)

> 왜: 목록이 "즐겨찾기 섹션 + 전체 섹션 + 큰 탭 + 상단 검색창 + 컬러 칩"으로 불어나면서
> 정작 관계에서 제일 중요한 **누구를 언제 마지막에 봤는지**가 묻혔다.
> 이 문서는 목록 화면이 다시 불어나지 않게 하는 검수 기준이다.
> 소속·태그의 데이터 규칙은 `docs/prd/02-person.md`, 색 규칙은 `design-system-gyeol.md`를 따른다.

## 정보 위계 (이 순서가 깨지면 회귀)

1. 얼굴(아바타) + 이름
2. 마지막 만남
3. 소속
4. 관계 태그

- [ ] 한 행에서 **마지막 만남**은 소속·태그보다 강한 대비(굵기 또는 색)를 갖는다.
- [ ] 이름 외 어떤 요소도 이름보다 시각적으로 크지 않다.

## 섹션·정렬

- [ ] 목록은 **하나의 그룹**이다. `즐겨찾기`/`전체` 같은 섹션 헤더를 두지 않는다.
- [ ] 즐겨찾기는 섹션이 아니라 **정렬 우선순위**로만 드러난다(어느 정렬이든 상단).
- [ ] 정렬은 `마지막 만남 순`(기본) · `기록 많은 순` · `이름 순` 3종이며 **Select**로 고른다.
      SegmentedControl·탭처럼 폭을 다 먹는 컨트롤을 쓰지 않는다.
- [ ] 정렬 컨트롤 높이는 32px(`size="sm"`) 이하다.

## 소속·태그 표시

- [ ] 소속은 **아바타 ring 색**으로 드러낸다. 목록에서 소속을 컬러 칩으로 그리지 않는다.
- [ ] 소속에 상위/하위가 있으면 텍스트는 **루트 라벨**, 하위는 **무채색 chip** 하나로 붙는다.
- [ ] 관계 태그는 `#태그` 텍스트다. 칩·색상을 쓰지 않는다.
- [ ] 소속이 없는 사람은 ring을 칠하지 않는다(무채색 유지).

## 헤더

- [ ] 제목은 `{username}님의 사람`. 카운트 문구는 `함께한 사람 N명` **하나뿐**이다.
      `전체 · N명`, `즐겨찾기 · N명` 같은 이중 카운트를 두지 않는다.
- [ ] 액션 순서는 `추가` → `검색`. 검색은 primary 자리(목록 상단 전폭 입력창)를 차지하지 않는다.

## 즐겨찾기 별

- [ ] 목록 행의 별은 18px(아이콘 24px의 75%)이다.
- [ ] 별은 행 진입(프로필 이동)과 히트영역이 겹치지 않는다.

## 검색

- [ ] 검색은 **전용 화면**(`/people/search`)에서 한다. 목록 화면에 상시 검색창을 두지 않는다.
- [ ] 검색 화면은 다음 상태를 모두 갖는다: 초기(최근 검색어) · 결과 있음 · 결과 없음 · 최근 검색어 없음.
- [ ] 최근 검색어는 **개별 삭제**와 **전체 지우기**가 모두 가능하다.
- [ ] 검색은 이름뿐 아니라 소속·관계 태그 라벨로도 걸린다.

## 배치

- [ ] 행·헤더·정렬 컨트롤은 `components/person/`의 순수 컴포넌트다(`component-placement.md`).
      데이터 로딩·mutation·화면 이동은 `stackflow/`가 소유한다.
