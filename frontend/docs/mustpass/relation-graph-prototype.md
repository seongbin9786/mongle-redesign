# mustpass — 인물관계도

> 왜: 지금까지의 관계 지도는 전부 **나 ↔ 그 사람**이다. "누가 누구를 아는가"(그 사람들끼리)는
> 다른 축이라, 궤도 안에 섞지 않고 별도 화면으로 연다.
> 배경: [docs/releases/2026-08-18-release.md](../../../docs/releases/2026-08-18-release.md)
> 서버 계약: [backend/docs/mustpass/07-relation-graph.md](../../../backend/docs/mustpass/07-relation-graph.md)

## 범위 계약 (must)

- [ ] 관계도는 **서버에 저장된다**(`GET·PUT /api/v1/relation-graph`). 노드의 **좌표까지** 저장한다 —
      관계도는 배치로 읽는 그림이라, 자리를 잃으면 선만 남아도 같은 그림이 아니다.
- [ ] 저장은 **사용자가 저장 버튼을 누를 때만** 한다. **자동 저장을 두지 않는다** —
      캔버스에서는 손이 지나가는 중간 상태(잘못 끈 선, 옮기다 만 자리)까지 저장될 수 있고
      되돌릴 방법이 없다. 언제 남길지는 그린 사람이 정한다.
- [ ] 저장 버튼은 머리 오른쪽 위에 늘 보이고, 상태를 말한다 — `저장`(보낼 게 있음) /
      `저장 중…` / `저장됨`(보낼 게 없어 눌리지 않음).
- [ ] 저장 안 된 변경은 **지금 화면 ↔ 마지막으로 서버와 맞춘 그림**을 비교해 판단한다.
      플래그로 들지 않는다 — 요청이 오가는 동안 또 움직여도 `저장됨`으로 잘못 넘어가면 안 된다.
- [ ] 저장에 **실패하면 기준선을 바꾸지 않는다**(버튼이 계속 `저장`으로 남아 다시 누를 수 있다).
- [ ] 저장 안 된 변경이 있는 채로 나가려 하면 **한 번 묻는다**(`저장하지 않고 나갈까요?`).
      자동 저장이 없으므로, 묻지 않으면 적어 둔 친밀도·메모가 말없이 사라진다.
- [ ] 화면 왼쪽 위 **뒤로 가기**로 나간다. 주소로 바로 들어와(새로고침·딥링크) 되돌아갈 화면이
      없으면 **홈으로 보낸다** — 눌러도 아무 일이 없는 버튼은 없는 버튼보다 나쁘다.
- [ ] 저장 단위는 **화면 전체**다. 부분 추가·삭제 요청을 만들지 않는다 — 한 번의 조작이
      노드·선·좌표를 동시에 바꾸므로, 쪼개면 중간 상태가 서버에 남아 화면과 갈린다.
- [ ] 서버 응답으로 화면을 **다시 씌우지 않는다.** 진입할 때 한 번만 받아 오고, 그 뒤의 진실은
      손에 있다. 저장 응답마다 덮어쓰면 끌던 노드가 뒤로 튄다.
- [ ] 관계의 **종류·방향을 만들지 않는다.** A→B와 B→A는 같은 선 하나이고, 같은 쌍을 두 번 이어도
      선은 늘지 않는다. 있는 건 '이어져 있다' + 친밀도 + 한 줄 메모까지다.

## 지도·영역 계약

- [ ] 화면은 자유 좌표 위의 점들이 아니라 **영역이 있는 지도**다. 무리는 한 구획을 차지하고,
      그 구획이 눈에 보여야 "이 사람들이 어떻게 묶여 있는가"가 한눈에 읽힌다.
- [ ] **선은 영역과 무관하다.** 구획은 보기 위한 것이지 이을 수 있는 범위가 아니다 —
      다른 구역의 누구와도 이어진다(그 교차가 이 화면에서 제일 보고 싶은 것이다).
      서버도 영역으로 선을 거르지 않는다.
- [ ] **소속은 놓은 자리가 정한다.** 인물을 구역 안에 떨어뜨리면 그 무리에, 바깥 들판에
      떨어뜨리면 어디에도 속하지 않는다. 지도에서는 위치가 곧 소속이라, 따로 고르게 하면
      화면이 말하는 것과 데이터가 갈린다.
- [ ] 구역이 겹치면 **위에 그려진(나중) 구역**이 이긴다 — 손끝에 보이는 게 그 구역이다.
- [ ] 어느 구역에도 안 든 인물은 **정상 상태**다(오류 아님). 구역 아래 들판에 놓인다.
- [ ] 구역은 **색칠된 안쪽 어디를 잡아도** 구획째 옮겨지고 **안의 인물도 함께** 간다
      (땅만 움직이고 사람이 남으면 구획이 깨진다). 지도에서 구역은 '땅'이라, 땅을 잡아 끄는 것이
      이름표를 정확히 겨냥하는 것보다 먼저 떠오르는 손짓이다. 이름표도 같은 손잡이로 남긴다 —
      구역이 사람으로 가득 차면 빈 바닥이 안 보인다.
- [ ] 구역을 지워도 **사람은 지도에 남는다** — 구획은 보기 위한 선이지 사람의 자격이 아니다.
- [ ] 사람이 다 빠진 빈 구역도 남긴다. "여기 자리를 잡아 뒀다"는 상태이고, 지우면 사람을 잠깐
      뺀 사이 지도의 구획이 무너진다.
- [ ] 지도는 화면보다 커질 수 있다 — **빈 바닥을 끌면 지도가 밀린다**(팬). 격자 바닥이 움직임을
      말해 주고, 처음 자리로 돌아가는 버튼은 밀리거나 배율이 바뀐 뒤에만 나타난다.

## 배율 계약

- [ ] **두 손가락은 어디서 시작하든 배율이다.** 손가락이 둘이면 그건 늘 확대·축소지 다른 무엇이
      아니다. 두 번째 손가락이 닿는 순간 끌던 것은 놓는다 — 확대하는 내내 사람이 딸려가면 안 된다.
- [ ] 손가락 장부는 **캡처 단계**에서 적는다. 노드·이름표는 자기 제스처를 지키려고 이벤트를 멈춰
      세우는데, 두 번째 손가락이 하필 그 위에 닿으면 캔버스가 영영 모르게 된다.
- [ ] 손가락이 둘일 수 없는 화면(마우스)에서는 **끌어서** 배율을 바꾼다 — 지도 위 배율 손잡이를
      위아래로 끈다(휠도 함께 받는다). 버튼 두 개로 두면 원하는 배율까지 여러 번 눌러야 하고,
      지금 얼마나 키웠는지도 알 수 없다.
- [ ] 배율이 바뀌어도 **초점(두 손가락 사이·커서 아래·화면 한가운데)의 지도 좌표는 그대로**다.
      그래야 '내가 그 자리를 확대했다'로 읽힌다.
- [ ] 배율은 40%~200% 안이다. 더 줄이면 얼굴이 점이 되고, 더 키우면 한 사람만 남아 지도가 아니게 된다.
- [ ] 화면 좌표 ↔ 지도 좌표 변환은 **한 곳**을 지난다. 배율을 빠뜨린 변환이 하나라도 있으면
      확대한 뒤 인물이 손끝에서 어긋난다.
- [ ] 인물 이름표는 **절대 배치 + `pointer-events-none`** 이다. 흐름에 두면 이름 칸이 카드 아래를
      차지해 연결 손잡이를 덮고, 이으려던 손이 옮기기로 잡힌다. 카드 크기를 아바타로 고정해야
      노드의 중심(x·y)이 아바타의 중심과 같아진다.

## 관계태그 불러오기 계약

- [ ] 인물 시트 맨 위에서 **관계태그를 누르면 그 무리가 한 구역으로** 지도에 놓인다.
      태그가 이미 "이 사람들은 한 무리"라고 말해 두었으므로, 지도에서 다시 손으로 모으게 하는 건
      같은 일을 두 번 시키는 것이다.
- [ ] 태그를 **참조하지 않고 이름·색만 복사**한다(서버도 같은 규약). 태그를 고치거나 지워도
      지도 위 구획은 사용자가 놓아둔 그대로 남아야 한다.
- [ ] 불러오기는 **이미 지도에 있던 사람도 그 구역으로 데려온다** — '불러오기'는 무리를 다시
      모으는 일이지 새 사람만 얹는 일이 아니다. 이어 둔 선은 인물 id 로 걸려 있어 그대로 남는다.
- [ ] 불러온 무리는 **서로 다 이어진 채로** 놓인다(n명 → n(n-1)/2 선, 친밀도 기본값 50).
      관계태그로 묶였다는 건 이미 "서로 아는 사이"라는 말이라, 그 안을 손으로 다시 이어야 한다면
      태그가 알려 준 사실을 버리는 셈이다.
- [ ] 이미 있는 선은 **덮어쓰지 않는다** — 사용자가 적어 둔 친밀도·메모가 기본값으로 되돌아가면 안 된다.
      그래서 같은 태그를 다시 불러도 선은 늘지 않는다.
- [ ] 선 한 쌍은 화면에서도 **작은 id 먼저**로 든다(서버와 같은 정규화). 모양이 다르면 저장하고
      돌아왔을 때 같은 선인지 매번 다시 따져야 하고, 다시 불러오기에서 중복이 생긴다.
- [ ] 인물(얼굴·이름)은 **선보다 위**에 그리고, 이름 뒤에는 바탕을 깐다. 한 무리를 통째로 부르면
      선이 그물처럼 겹치는데 그 아래에 얼굴과 이름이 깔리면 지도가 아니라 낙서가 된다.
- [ ] 같은 태그를 다시 부르면 구역이 **하나 더 생기지 않고** 크기만 인원수에 맞춰 다시 잡힌다.
- [ ] 구역 크기는 인원수가 정한다(한 줄에 세 명까지). 사람이 늘면 구역도 자란다 — 넘쳐 흐르지 않는다.
- [ ] 새 구역은 **지금까지 놓인 것 전부(구역 + 들판의 인물)의 오른쪽**에 놓는다. 겹쳐 놓으면
      어느 구역인지 알 수 없고, 사람 위에 구역이 덮이면 그 사람이 그 무리인 줄 알게 된다
      (지도에서는 위치가 곧 소속이다).
- [ ] 새 인물도 같은 규칙으로 **놓인 것들 아래**에 놓는다. 자리 계산의 기준은 '남는 사람'이다 —
      방금 체크를 푼 사람의 자리까지 피하면 새 사람이 빈 들판 저 아래에 떨어진다.

## 진입 계약

- [ ] 홈 탭 헤더 **오른쪽 위** 버튼(`인물관계도`)으로 들어간다. 홈의 궤도(나 중심)와
      다른 축이라 궤도 안에 섞지 않고 별도 화면(`/relation-graph`)으로 연다.
- [ ] 홈 하단 탭에 항목을 늘리지 않는다(탭 구성은 확정 계약 → PRD 01 §9).

## 인터랙션 계약

- [ ] 인터랙션은 **셋뿐이다**: 노드를 끌어 옮긴다 / 노드에서 다른 노드로 끌어 잇는다 /
      이어진 선을 눌러 그 사이를 적는다.
- [ ] 앞의 둘을 가르는 건 **시작점**이다 — 아바타에서 시작하면 이동, 오른쪽 아래 ＋ 손잡이에서
      시작하면 연결. 모드 토글을 두지 않는다(확인하려는 게 모드 전환이 아니다).
- [ ] 잇는 중에는 손끝까지 점선이 따라오고, 놓은 자리에 노드가 없으면 아무 일도 일어나지 않는다.
- [ ] 선은 1~5px 이라 손끝으로 짚을 수 없다 — 보이는 선 위에 **넓은 투명 선**을 겹쳐 눌리게 한다.
- [ ] 빈 상태에서 다음 동작(＋로 인물 올리기 → 인물 옆 ＋를 끌어 연결 → 선을 눌러 적기)을
      문장으로 알려 준다.

## 인물 올리기 (체크리스트 시트)

- [ ] 올릴 사람은 **실제 인물 목록**에서 고른다(가짜 이름을 만들지 않는다). 시트는 후보만
      추리지 않고 **전체 목록을 체크리스트로** 보여 준다 — 이미 올린 사람은 체크된 채로 보이고,
      체크를 풀면 지도에서 내려간다(= 시트의 체크 상태가 곧 지도에 올라간 사람).
- [ ] 체크하는 동안에는 지도를 건드리지 않고, **담기 버튼 한 번**으로 올리고 내리기를 함께
      반영한다. 한 명 고를 때마다 뒤 지도가 움직이면 고르는 도중에 자리가 다 바뀐다.
- [ ] 시트 맨 위에 **검색 인풋**을 둔다(이름·소속, 화면 안에서 거르기). 사람이 수십 명이면
      스크롤로 찾는 게 고르는 일보다 오래 걸린다.
- [ ] 사람을 내리면 그 사람에게 걸려 있던 **선도 함께 사라진다**(양끝이 다 지도에 있어야 선이다).
- [ ] 새 노드는 **아바타보다 넓은 간격의 격자**로 벌려 놓는다. 조금씩만 어긋나게 놓으면
      뒤 노드가 앞 노드의 연결 손잡이를 덮어, 이으려던 손이 옮기기로 잡힌다.

## 친밀도·메모 (선 시트)

- [ ] 선을 누르면 **두 사람 이름**을 제목으로 한 시트가 열리고, 거기서 **친밀도(0~100)** 와
      **"어떻게 아는 사이"(한 줄, 200자)** 를 적는다.
- [ ] 친밀도는 숫자 입력이 아니라 **끌어서 정하는 바**다. 62와 65의 차이를 사용자가 설명할 수
      없으므로 정확히 찍게 하지 않는다. 키보드(←/→)로도 움직여야 한다.
- [ ] 눈금에는 **양 끝에만** 말을 붙인다(`먼 사이`·`가까운 사이`). 중간마다 이름을 붙이면
      사용자가 자기 감각 대신 그 낱말에 값을 맞춘다.
- [ ] 시트의 값은 **저장을 눌러야** 지도로 넘어간다. 끄는 동안 뒤 지도가 계속 다시 그려지면,
      시트에 가려 보이지도 않는 변화 때문에 저장 요청만 계속 나간다.
- [ ] 시트에서 **연결 끊기**로 그 선만 지울 수 있다(노드는 남는다).
- [ ] 갓 이은 선은 **50**에서 시작한다 — 가운데여야 올리는 손짓과 내리는 손짓의 거리가 같다.

## 색 계약

- [ ] 선 색은 친밀도를 따라 **낮으면 파랑 → 가운데는 먹색 → 높으면 빨강**, 세 지점을 이어서
      섞는다. 단계를 나누지 않는다(값이 연속이니 색도 연속이어야 손끝과 눈이 같이 움직인다).
- [ ] 가운데를 무채색으로 두는 이유: "아직 어느 쪽도 아니다"가 색으로 읽히고, 파랑과 빨강이
      서로를 흐리게 만드는 보라 구간도 사라진다.
- [ ] 양 끝 색은 **관계태그 팔레트**에서(`블루` `#2563EB` → `코랄` `#F43F5E`), 가운데 색은
      **테마 토큰**(`--foreground` = `--gyeol-ink-90` = `oklch(0.271 0.009 285.8)`)에서 가져온다.
      여기서만 쓰는 색을 새로 정의하거나 토큰 값을 hex 로 베껴 두면, 팔레트·테마와 갈린다.
- [ ] 섞는 일은 JS 가 아니라 **CSS `color-mix(in oklab, …)`** 이 한다(가운데 색이 토큰이라 JS 로
      계산하려면 값을 베껴 와야 한다). 반환값이 CSS 색 문자열이므로 SVG 에는 속성이 아니라
      `style` 로 넘긴다.
- [ ] 색만으로 구분하지 않는다 — 친밀도가 높을수록 **선도 굵어진다**(색약·흑백 화면).
- [ ] 선 색·바 색·손잡이 색은 **한 곳**(`lib/intimacy-scale.ts`)에서 나온다. 같은 값인데 화면마다
      다른 색이 나오면 안 된다.
