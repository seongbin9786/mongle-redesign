# mustpass — 존과 우주 스와이프

> 왜: 홈의 관계태그 칩 필터를 걷어내고, 사용자가 이름 붙인 **존**을 좌우로 넘기는
> **우주**로 바꾼다. 칩은 화면 위쪽 한 줄을 늘 차지하면서 "무엇을 고를지"를 먼저 묻는데,
> 홈에서 하고 싶은 일은 고르기가 아니라 **보기**다. 우주는 고르지 않아도 첫 장이 열리고,
> 더 보고 싶을 때만 옆으로 넘긴다.
> 배경: [docs/releases/2026-08-18-release.md](../../../docs/releases/2026-08-18-release.md) ·
> 서버 계약: [backend/docs/mustpass/06-zone.md](../../../backend/docs/mustpass/06-zone.md)

## 우주 구성 계약

- [ ] 우주 목록 = **`전체` + 존 순서대로 + `만들기`**. 첫 장은 언제나 `전체`, 마지막 장은
      언제나 존을 만들러 가는 안내 장이다.
- [ ] **존이 0개여도 넘길 곳이 있어야 한다.** 스와이프는 흔적을 남기지 않는 제스처라,
      넘길 장이 없으면 기능이 있다는 사실 자체가 드러나지 않는다 — 설정에 들어가 본 사람만
      아는 기능이 되면 안 된다. 그래서 존이 없을 때도 `전체` + `존 만들기` 두 장이다.
- [ ] 만들기 장은 **존 상한(12, 서버 `ZONE_MAX`와 같은 값)에 닿으면 접는다** — 눌러도 실패할
      장을 남기지 않는다. 프런트 상수가 서버보다 크면 그 장이 남는다.
- [ ] 만들기 장의 이름은 존이 없으면 `존 만들기`, 있으면 `새 우주`다(첫 사용자에게 필요한 말과
      이미 만든 사용자에게 필요한 말이 다르다). 인디케이터에서 점을 테두리만 남겨 우주와 구분한다.
- [ ] `전체`와 `만들기`는 존이 아니다 — 서버에 대응물이 없는 가상 장이다(`kind`로 가른다).
      인물 0명(콜드스타트)일 때는 인디케이터·만들기 장을 보이지 않는다(사람이 먼저다).
- [ ] **비어 있는 존도 우주로 남는다.** 방금 만들고 아직 사람을 안 담은 상태는 정상이고,
      여기서 접으면 "만든 존이 홈에 없다"가 된다. 빈 우주에는 사람 담으러 가는 안내를 띄운다.
- [ ] 존 우주는 **숨기지 않고 뺀다** — 안 담긴 사람은 흐리게가 아니라 그 우주에 아예 없다.
      (흐림은 `멀어진 관계` 전용 표현이라 섞지 않는다 → `orbit-home-gyeol.md`)
- [ ] 우주를 넘겨도 **관계 지도는 다시 부르지 않는다.** 한 번 받은 노드를 존의 personIds로
      나눌 뿐이다 — 우주마다 서버를 다녀오면 스와이프 도중 지도가 비어 은유가 깨진다.
- [ ] 궤도 위 자리는 우주가 바뀌어도 **경과일이 정한다.** 존 안의 인물 순서(personIds)는
      배치에 영향을 주지 않는다(반경은 경과일의 함수 → `orbit-home-gyeol.md`).
- [ ] 존을 지워 우주 수가 줄면 보고 있던 자리를 마지막 우주로 당긴다(빈 화면 금지).
- [ ] 우주 구성·다음 인덱스 계산은 `lib/home-universes.ts`의 순수 함수이고 단위 테스트가 있다.

## 제스처 계약

- [ ] **제스처 중재자는 `use-orbit-viewport.ts` 하나다.** 스와이프를 바깥 래퍼에서 따로 받지
      않는다 — 같은 포인터를 두 곳이 해석하면 지도 팬과 우주 이동이 서로를 삼킨다.
- [ ] 우주 이동으로 읽는 조건은 셋 다 만족할 때뿐이다: ① 기본 보기(확대·이동하지 않은 상태)
      ② 가로 이동이 세로의 1.4배 초과 ③ 손을 뗄 때 가로 이동 56px 이상.
      확대해서 보는 중의 가로 드래그는 **언제나** 지도를 미는 뜻이다.
- [ ] 제스처의 정체(팬/스와이프)는 임계값을 넘는 **첫 움직임**이 확정하고 끝까지 바뀌지 않는다.
      도중에 바뀌면 지도가 튀고 우주도 어중간하게 끌린다.
- [ ] 끝 우주(양 끝)에서는 **끌리지도 않는다** — 고무줄처럼 늘어났다 돌아오면 넘어갔는지를 묻게 된다.
      우주는 순환하지 않는다(순환하면 인디케이터 없이는 한 바퀴 돈 걸 알 수 없다).
- [ ] 끄는 동안 지도는 손가락의 35%만 따라온다. 1:1로 붙으면 넘길 마음이 없던 손짓도 이동처럼 보인다.
- [ ] 스와이프로 판정된 제스처는 **노드 클릭을 삼킨다**(팬과 같은 규칙).

## 표현 계약

- [ ] 우주가 바뀌면 새 궤도가 **넘긴 방향에서** 들어오며 그려진다(`orbit-universe-in`, 420ms).
      나가는 우주를 함께 그리지 않는다 — 눈금이 두 겹으로 보이면 어느 쪽이 내 우주인지 흐려진다.
- [ ] **첫 렌더에는 도착 애니메이션을 걸지 않는다**(enterDirection 0). 홈에 들어오자마자
      궤도가 옆에서 밀려 들어오면 넘긴 적 없는데 넘어간 느낌이 된다.
- [ ] 끌림(손끝 추종)과 도착(애니메이션)은 **다른 레이어**다. 한 요소에 두면 끄는 도중
      우주가 바뀔 때 두 transform이 서로를 덮어쓴다.
- [ ] `prefers-reduced-motion`에서 도착 애니메이션은 꺼진다.
- [ ] 인디케이터는 **이름 + 점**이고 좌우 화살표 버튼을 함께 둔다(스와이프를 모르는 사람·마우스).
      존 이름은 사용자가 지은 말이라 `data-amp-mask` 대상이다.

## 우주 목록 시트 계약

- [ ] 인디케이터의 **이름을 누르면 우주 목록 시트**가 열리고, 고르면 그 우주로 바로 간다.
      스와이프만으로는 끝에서 끝까지 존 수만큼 손이 들어, 존이 늘수록 닿는 거리가 길어진다.
- [ ] 목록이 인디케이터를 대신하지 않는다 — 목록은 "어디로 갈까"를, 인디케이터는 "지금 어디쯤인가"를
      맡는다. 이름이 눌린다는 사실은 **⌄ 표시**로 말한다(이름만으로는 눌러 볼 이유가 없다).
- [ ] 목록에는 `전체` + 내 존만 담고 **'만들기' 장은 빼**다. 여기서 고르는 건 **볼 우주**이고,
      존을 만드는 일은 고르는 일과 다른 종류의 행동이다.
- [ ] 각 줄은 **존 색 · 이름 · 인원 수**를 보이고, 지금 보고 있는 우주에 체크(`aria-current`)를 남긴다.
- [ ] 목록에서 골라 와도 **도착 방향은 목록 순서**(지금보다 뒤면 →, 앞이면 ←)로 정한다.
      방향 없이 갈아 끼우면 넘긴 건지 바뀐 건지 구분되지 않는다.

## 존 설정 계약

- [ ] 설정 > **존 관리**(`/settings/zones`)에서 만들고, 이름·색을 고치고, 지운다.
      태그 설정의 부품(`TagCreateRow`·`TagInlineEditor`·`RelationTagColorPicker`)을 재사용한다 —
      같은 종류의 편집에 다른 조작감을 만들지 않는다.
- [ ] 존 줄의 **주 동작은 '들어가기'** 다(누르면 인물 담기 화면). 이름 수정·삭제는 오른쪽 보조 버튼.
- [ ] 인물 담기(`/settings/zones/:zoneId`)는 **고르는 동안 서버를 건드리지 않고**, 저장 한 번으로
      전체를 교체한다(서버 계약이 전체 교체다 → `06-zone.md`).
- [ ] 존을 지워도 사람은 지워지지 않는다 — 삭제 확인 문구가 이 사실을 말한다.
- [ ] 존이 바뀌면 zones 쿼리만 무효화한다(관계 지도는 그대로다 — 우주 구성만 바뀐다).
